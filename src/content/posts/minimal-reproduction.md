## 先固定一个能够观察的差异

“功能不正常”还不足以开始缩小问题。先描述明确的输入、执行步骤、预期结果和实际结果，再确认同样的步骤是否能重复触发。若问题只在某个环境出现，应记录相关版本和配置。稳定的观察对象能帮助判断后续删减是否仍然保留了原问题。

例如，列表金额相加后结果异常，可以先把接口请求、页面组件和样式移开，只保留参与计算的数据与表达式。下面的片段已经能够展示现象：

```js
const amounts = ["10", "2"];

const result = amounts.reduce((sum, value) => sum + value, 0);
console.log(result); // 实际得到字符串 "0102"，预期为数字 12

const numericResult = amounts.reduce((sum, value) => sum + Number(value), 0);
console.log(numericResult); // 12
```

这个例子将注意力集中到数据类型与加法运算。显式转换可以解释这组输入的结果，但真实系统仍需明确输入规则；空字符串、缺失值或非数字文本应该如何处理，是另外需要验证的条件。

## 一次移除一个条件

删减时可以从无关页面、外部服务、数据字段和配置项开始。每删去一部分，就重新执行复现步骤。如果现象消失，恢复刚才移除的部分，再把它继续拆小。保留一份能够复现的版本，可以避免删减过头后失去判断基准。

### 让别人能够独立运行

一个实用的复现应交代运行环境、必要文件和操作步骤，并直接展示实际输出。数据尽量使用结构相同的虚构样本，移除无关依赖。若仍需访问复杂服务或补全大量背景知识，说明复现还有继续缩小的空间。

## 用复现验证解释是否成立

最小复现除了帮助提问，也能检查自己的判断。提出一个原因之后，尝试只改变与这个原因有关的条件，观察结果是否按预期变化。最后把修正应用回原来的场景，再重复最初的触发步骤。小例子解释了一个机制，完整场景则确认这个机制是否确实造成了眼前的问题。
